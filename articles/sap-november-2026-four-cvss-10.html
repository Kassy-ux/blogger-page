Four Perfect Tens in the SAP Kernel

SAP’s November patch day shipped four CVSS 10.0 fixes and withheld the exploitation detail. The mechanism is not exotic, the configuration gate is quiet, and the public record stops short of a victim.

By Stancy Ngereso · November 10, 2026 · Riftweld research briefing · SAP November 2026

SAPCVSS 10.0Pre-auth RCEGatewaySAML

For years, the working assumption behind most SAP patching programmes has been that the kernel is the part you update on a schedule, and that the dangerous bugs live in custom code. The November 2026 security notes do not support that assumption. Four of them carry the maximum CVSS score of 10.0, and three describe ways to run operating-system commands on the SAP host without a credential. What the disclosure does not contain is the evidence that usually turns a score into an incident: a confirmed victim, or a scan.

The shape of the month is not subtle. RedRays, reviewing SAP for Me on 10 November, counted 38 notes with that release date: nine HotNews, thirteen High, fifteen Medium and one Low. Four of those notes score 10.0. As RedRays put it, “SAP released 38 security notes on Patch Day, nine of them HotNews, and four of those score the maximum CVSS 10.0.” The same review is blunt about why they matter: “None of the four needs credentials: a SAML2 signature bypass in AS ABAP, a weakness in SAP Gateway’s default access control list, and a WebSocket heap overflow that hits both SAP Web Dispatcher and the ABAP ICM.”

Yet the public record is thinner than the scores. Onapsis Research Labs, which found and reported the kernel and gateway flaws, deliberately withheld exploitation detail from its advisories, saying the posts are aimed at exposure assessment and remediation rather than reproduction. The Hacker News notes that the notes themselves sit behind a sign-in: “The notes are in SAP for Me, which requires a sign-in, and the vendor strongly recommends applying them as a priority.” What is public is the CVE identifiers, the affected components and the configuration gates. What is not public is a working exploit, a victim, or a scan.

On 10 November, Onapsis published two advisories that, together, explain most of the month’s risk. The first, ICM2SHELL, covers CVE-2026-76964 and CVE-2026-89126; the second, PROXYGATE, covers CVE-2026-89103. The most tangible detail is architectural: the SAP Web Dispatcher is built on the same kernel code as the Internet Communication Manager, so it does not merely forward the traffic that reaches the edge. It reassembles WebSocket messages itself, using the vulnerable code. “Because that code is shared by the ICM and the SAP Web Dispatcher,” Onapsis writes, “both are affected, including the component that usually faces the Internet.”

The consequence is command execution as <sid>adm, the operating-system account that owns the SAP installation, its instance profiles, its secure store and its database connectivity. That is not an application-level foothold. It is the identity under which the instance runs, and it is the identity an attacker needs to read or alter business data directly in the database, to harvest RFC destinations and technical credentials, to change configuration or binaries for persistence, and to stop the system outright.

The flaw is not theoretical, but it is also not yet observed. “As of the date of this publication, the Onapsis Research Labs have not observed active in-the-wild exploitation of this vulnerability,” the ICM2SHELL advisory states. The same posture applies to PROXYGATE. Onapsis says it supplied SAP with a working exploit that achieved full unauthenticated remote code execution end to end, running arbitrary commands as <sid>adm, and it reproduced the denial-of-service condition on every kernel release it tested. The absence of a victim, in other words, is a statement about the clock, not about the bug.

The operational weight is easiest to see on a production ERP system. “On a production ERP system,” Onapsis writes, “that means direct exposure of the business data, transaction integrity, and the availability of critical business applications.” The denial-of-service leg deserves separate emphasis because it is unconditional: the same bug can crash either component, and a crashed Web Dispatcher cuts off every SAP system behind it while it restarts.

The reach is not confined to one deployment shape. The affected surface runs across the ABAP kernel, the ICM, the standalone Web Dispatcher, the Web Dispatcher embedded in SAP HANA XS, the SAML 2.0 service provider in ABAP Platform, and the native SAP Gateway across ABAP, AS Java, dual-stack and standalone installations. Affected ICM and Web Dispatcher versions include KRNL64UC 7.53 and KERNEL 7.53, 7.54, 7.77, 7.93, 9.16, 9.18 and 9.20; affected Gateway versions run from KRNL64NUC 7.22 through KERNEL 9.21. Onapsis additionally lists older kernels — 7.40, 7.41, 7.42, 7.45, 7.49, 7.73, 7.81, 7.85 and 7.89 — that may never receive a fix at all.

The vendor’s framing and the researchers’ framing agree on severity and diverge on timing. SAP’s catalogue calls them priority fixes. The researchers call them working primitives whose disclosure window has just opened. Both are consistent with the same operational fact: the identifiers and the configuration gates are now public, which is the point at which opportunistic scanning usually begins, regardless of whether a public exploit exists.

The highest-value targets are internet-facing landscapes. A Web Dispatcher exposed to the internet, an ICM reachable through a published HTTP/HTTPS endpoint, and a Gateway reachable from an untrusted network all sit directly in the path of an unauthenticated adversary. The ICM path needs only network reachability to the HTTP/HTTPS port and a crafted sequence of WebSocket messages that drives an out-of-bounds write during fragment reassembly. No credential, no user interaction, and no misconfiguration are required; in some configurations the flaw is reachable before authentication, and SAP S/4HANA ships with ICF services that accept WebSocket connections without authentication.

But the researchers are careful about the distinction between exposed and exploited. Onapsis has not seen the bug in attacks. The Hacker News reports the same: “The company’s researchers have not seen the bug exploited in attacks.” That absence changes the tempo of the response, not the severity of the bug. A CVSS 10.0 that runs commands as the instance owner is a full-compromise primitive on the day it is published, whether or not anyone has fired it yet.

The Gateway’s Blind Spot

The gateway flaw is the more interesting of the two, because it is a policy failure wearing the costume of a memory bug. SAP Gateway is the component through which other systems make RFC calls, where external RFC servers register, and the mechanism that can start helper programs on the host. It runs by default on every SAP NetWeaver ABAP application server, and the same native gateway also runs in AS Java, dual-stack and standalone deployments.

Its access model rests on three lists: secinfo, which decides who may start which programs and where; reginfo, which decides which external programs may register; and prxyinfo, which decides which connections the gateway may relay or open on behalf of a client. Hardening guidance has concentrated on the first two, and the community’s summary of them is uncompromising: “trust the SAP system’s own hosts and nothing else.” The blind spot is the third list. “PROXYGATE attacks that conclusion,” Onapsis writes. Where the proxy policy allows it, a crafted series of requests makes the gateway believe an unauthenticated external request came from an internal application server. The access lists then behave exactly as configured, the “allow internal” rule is satisfied, and the gateway starts what the attacker asked for — in the most severe case, an arbitrary operating-system command as <sid>adm.

The gate is prxyinfo, or the profile parameter gw/acl_mode_proxy when the file is absent. A restrictive policy prevents the attack from starting; permissive configurations, including some defaults, leave the system exposed. Onapsis is explicit about the exposed population: “Systems with a permissive prxyinfo, or with no prxyinfo and the parameter not set to 1, are your exposed population.” And its first instruction is equally direct: “Restricting it should be your first action.”

On most kernel releases, SAP’s fix combines a kernel patch with setting gw/acl_mode_proxy = 1; RedRays notes that the kernel fix adds the parameter for kernels up to 7.77 and advises ensuring secinfo and reginfo hold explicit rules rather than relying on implicit defaults. That is the uncomfortable part of the month: for the gateway, patching alone can leave the condition in place. The configuration is not a compensating control. It is half the fix.

The same logic explains why the gateway is a soft spot out of proportion to its CVE count. It is a trust point by design: it exists to let systems talk to systems, and its lists encode who is allowed to do what. Any flaw that lets an outsider be mistaken for an insider borrows the entire trust model rather than breaking it, which is why a permissive prxyinfo is worse than a missing patch. The gateway does not need to be compromised to be dangerous. It needs to be believed.

The ICM path is the more mechanical of the two. A WebSocket connection begins as an ordinary HTTP upgrade request; large messages may be split into fragments the receiver must recombine before handing them to the application. A crafted sequence writes attacker-controlled data past the end of the memory reserved for the connection, producing either an immediate crash or controlled corruption that the attacker converts into commands as <sid>adm. RedRays describes the same defect as malformed WebSocket control frames causing a heap out-of-bounds write before authentication. Onapsis reproduced the crash on every kernel release it tested.

The SAML fix is the quiet one. Under certain configurations, the SAML 2.0 service provider in AS ABAP and ABAP Platform did not verify signatures on incoming assertions, allowing an attacker to forge a response and log on as any user, administrators included. It requires no exploit primitive at all — only a forged assertion — and RedRays states there is no workaround. It is also the flaw most likely to be skipped during a kernel-focused rollout, because it lives in the service provider rather than the kernel or dispatcher. Enumerate every Fiori and Web GUI system using SAML SSO; configuration review alone does not close it.

The instinct to read a 10.0 as a vendor-communication artefact — a number chosen to move a customer — is understandable and, this month, wrong. The value of the score is not the score. It is the configuration the score sits on: a default-enabled WebSocket stack, a dispatcher that is the first process to parse hostile input, a gateway that runs on every application server, and a proxy list that most hardening guides never mention. The kernel was supposed to be the boring part.

The re-entry risk is not a second exploit; it is the scan. The CVE identifiers, affected components and configuration gates are now public, and the affected-version lists are long. The out-of-maintenance kernels — 7.40, 7.41, 7.42, 7.45, 7.49, 7.73, 7.81, 7.85 and 7.89 for ICM2SHELL, plus 7.20 and 7.21 for PROXYGATE — are the population that will not be fixed by a note. Those systems need an upgrade to a maintained release, and until then the only honest control is network reachability.

Taken together, the four fixes describe a single thesis. The dangerous part of an SAP landscape is not the business logic an attacker can reach; it is the infrastructure that decides whether the attacker is allowed to reach it. The ICM decides whether a WebSocket frame is parsed as a message or as a memory write. The gateway decides whether an external caller is an external caller or an application server. SAML decides whether an assertion is a signature or a suggestion. The trust decision is the vulnerability.

The most useful sentence of the month may be the least dramatic one. “For the SAP Security Patch Day November 2026, most of the critical fixes are in the kernel, so the practical answer for many landscapes is one well-planned kernel and Web Dispatcher rollout,” RedRays writes. The SAML bypass, CVE-2026-120017 in SAP_BASIS releases 702 through 922, is the exception that a kernel-only rollout will miss: there is no workaround, so systems using SAML single sign-on need the service-provider fix regardless of what the dispatcher team does. The advisories are at Onapsis ICM2SHELL and PROXYGATE, RedRays and The Hacker News.
